How to add a new programmer¶

If you plan to add a new programmer, firstly double-check that none of the existing programmers works for you.

If in doubt, you are welcome to start a thread on the mailing list, or join the real-time channel Contact.

To add a new programmer, you will need to create a commit, test it, and send it for review.

If this is the first time you contribute to flashrom, please read carefully the Development Guide, and set up your local dev environment.

There are several places to update, all these need to be included in the patch which adds the programmer:

  1. Source code in programmers/ directory

  2. Test for it in tests/ directory

    1. we aim to have tests for all new programmers that have been added since the time flashrom has tests (old programmers might not have one)

    2. this involves 3 files in tests/ directory: source code of new test, and registering it in tests/tests.c, tests/tests.h

    3. check that your new test runs together with other tests

  3. Build system

    1. meson.build

    2. meson_options.txt

    3. check that new programmer builds and enabled when the option enabled, and does not build when it's disabled

  4. test_build.sh - jenkins runs this script

  5. Header include/programmer.h

  6. Table programmer_table.c

  7. Documentation

    1. manpage Manual page

    2. recent development doc Recent development (unreleased)

  8. Testing information

    1. test all operations with new programmer

    2. add testing info to the commit message

  9. Will you take the responsibility to be a maintainer for your new programmer? The responsibility is only your programmer, not everything that is happening on flashrom.

    1. the preference is, of course, for the authors to be the maintainers of their programmer

    2. you will care that the programmer is in good working condition, especially testing before the release

    3. relevant document: Team

    4. this means adding yourself to MAINTAINERS file
